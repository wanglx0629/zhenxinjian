# ADR 0004: 计算口径以后端为唯一真源

- 状态：Accepted
- 日期：2026-09-04

## 背景

BMR/TDEE/宏量计算是产品核心价值，且 9/3 图片公式定稿后口径精细（碳循环日型除数 2/2.2/2、周期线性放大、±1g 守恒）。若前端自行计算入库，存在参数篡改、多端口径漂移风险。小程序端 PRD 亦要求「前端计时仅展示，核心时效 / 权限 / 数据迁移由后端校验」。

## 决策

1. **一切健康计算（BMR / TDEE / 碳循环图片公式 / 532 占比 / 经期加碳 / 平台期调碳 / 食物宏量换算）在后端完成**并落库；前端只做实时预览，**以后端返回为准**。
2. **区间校验前后端双重**：前端标红提示，后端 `@Valid` + Service 业务区间二次兜底拒绝。
3. **常量口径固化在代码常量 / 配置**（除数 2/2.2/2、活动系数、占比 50/30/20、cfc 0.8/1.0），禁止散落魔法值。
4. 计算函数作为**纯函数**实现（无状态、可单测），是 khufu-ut 的重点覆盖对象。

## 后果

**正向**：口径唯一、可验证（EVAL-002/003 直接断言后端返回）；防篡改；公式纯函数化使单元测试可精确覆盖 241/23、153/49、72/77 等定稿样例。

**负向 / 权衡**：前端预览与后端计算需保持公式一致（预览仅展示用途，最终以后端覆盖）；每次输入变化多一次交互延迟（可接受，性能预算 ≤1s）。
