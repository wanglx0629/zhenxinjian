# ADR 0003: 软删除与活跃唯一约束策略

- 状态：Accepted
- 日期：2026-09-04

## 背景

全局规则要求用户数据永久留存（饮食记录、自定义食物被历史引用后不可物理删除），同时存在唯一性需求（同一用户下自定义食物名称不可重复）。MyBatis-Plus 已启用逻辑删除（`deleted` 0/1）。

## 决策

1. **业务删除一律软删**（`deleted` + PO `@TableLogic`），特殊清理脚本除外；自定义食物被历史饮食记录引用时标记 `status = 停用` 而非删除。
2. **饮食记录冗余存储食物快照**（`food_name` / 单位 / 份量 / 宏量），食物停用后记录不丢失。
3. **软删后仍需唯一的列**用 MySQL **生成列**实现活跃唯一，不对可空业务列直接加普通 UNIQUE：

```sql
username_active VARCHAR(64) GENERATED ALWAYS AS (IF(deleted = 0, username, NULL)) STORED,
UNIQUE KEY uk_xxx_username_active (username_active)
```

4. 乐观锁：需要并发控制的表（如 `users`）加 `version` + `@Version`。

## 后果

**正向**：历史记录完整（验收标准 3）；唯一性与软删共存；审计可追溯。

**负向 / 权衡**：查询需注意 `deleted` 过滤由 MP 自动处理，手写 SQL 别忘带条件；生成列增加写放大（可接受）。
