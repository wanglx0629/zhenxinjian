| 定义 | 系统任何时刻都必须成立的普适规则，**永不违反**；每条附验收锚点 |

1. **数据永久留存**：所有用户数据（个人资料、减脂模式、周期、饮食、体重）永久云端留存，不自动清空。（验收：任意历史日期饮食 / 周期数据可查）
2. **切换模式即重置**：切换减脂模式自动终止当前周期、清空当期进度、重启全新周期；历史数据不受影响。（EVAL-006）
3. **免责声明不可移除**：一切健康计算结果必须内置免责声明——仅作生活化减脂参考，非医疗建议。（EVAL-018）
4. **计算口径唯一**：BMR / TDEE / 碳循环图片公式 / 532 占比以后端计算为唯一真源；碳循环日型除数固定 2/2.2/2，周期长度线性放大（7→2/2.2/2，14→4/4.4/4），禁止动态重算；碳+脂周分配比例恒守恒 100%；周期总量守恒允许 ±1g。（EVAL-003/004）
5. **调碳兜底**：平台期判定 = 最近 7 天体重记录（≥2 条）最大值 − 最小值 < 0.3kg（每周一空腹称重为标准采集点）；触发后单次仅降碳水 20g（总热量 −80kcal），禁止连续多周递减；体重恢复下降即停止下调、维持当前配比；经期四阶段自动上浮——经期 +15g 碳水 / +60kcal、排卵期 +5g / +20kcal、黄体期 +10g / +120kcal（卵泡期基线不变），蛋白脂肪均不变。（EVAL-009/010）
6. **游客规则**：游客 3 天完整功能体验；到期强制授权弹窗不可关闭；时效 / 权限 / 数据迁移由后端校验；临时数据保留 7 天后清空；登录后自动迁移合并。（EVAL-007/008）
7. **输入区间**：年龄 12–80、身高 100–250cm、体重 25–200kg、目标体重 25–200kg 且 ≤ 当前体重；前后端双重校验，后端兜底拒绝。（EVAL-001/005）
8. **引用完整性**：自定义食物被历史饮食记录引用后只能软删 / 停用，不物理删除；饮食记录冗余存储食物快照。（EVAL-011）
9. **数据归属**：用户仅能操作自己的自定义食物、饮食记录、提醒设置；内置食物库只读；管理端接口须 ADMIN 角色。（EVAL-017）
10. **减脂缺口基准**：532 与碳循环共用「基准热量 = TDEE − X」，X ∈ {200, 300, 400, 500} 默认 200；碳循环中 X 不参与宏量核算，仅用于档案 / 承诺值统一展示。
11. **克数精度**：单日克数四舍五入（计算保留 1 位小数，UI 展示整数克）；后端按 double 存储防累计漂移；宏量守恒校验（蛋白×4 + 脂肪×9 + 碳水×4 ≈ 热量 ±10%，自定义食物入库时强制）。（EVAL-012）
12. **提醒单次性**：每日饮食提醒单次；已记录饮食当日不再重复推送。（EVAL-020）
13. **食物库数据口径**：内置食物 200 条（F001–F200，10 大分类），营养值按《中国食物成分表》第 6 版、每 100g 可食部；能量按 4/4/9 换算（与实测值最大偏差 ±0.5，属参考值）；干制品一律按干重标注不做泡发换算；同一食物生/熟态分列条目；数据真源 `doscFile/projectFile/04-食物库数据字典.md`，前端内置 `src/data/foods.ts` 仅离线兜底。
