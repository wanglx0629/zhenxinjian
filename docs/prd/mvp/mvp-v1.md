## 目标

帮助健身减脂新人小白完成「算得准、记得快、有提醒、能坚持」的生活化减脂第一步：核心计算 + 食物库 + 记录 + 提醒四大能力闭环，小白零学习成本完整使用。

## 范围内功能

| 模块 | 功能点 |
| ---- | ------ |
| 账号 | 微信一键授权登录（openid 唯一绑定）；登录态持久化；授权失败重试；**游客 3 天完整功能体验**（到期强制授权弹窗不可关闭；数据登录后自动迁移，过期 7 天清空；后端兜底校验） |
| 核心计算 | BMR（Mifflin-St Jeor）→ TDEE（4 档活动系数）→ 基准热量 = TDEE − X（X 自选 200/300/400 默认 200）；宏量输出 |
| 532 碳水渐降 | 固定占比 碳 50/蛋 30/脂 20；自然月 4 阶段（适应/经期 +15g 碳/+60kcal/经后高效/平台突破）；每周一空腹称重、2 周观测、平台期 −20g 碳/−80kcal、禁止连续递减 |
| 碳循环 | 输入：当前/目标体重（≤ 当前）、周期 5/7/10/14（默认 7）、cfc 0.8/1.0（默认 0.8，持久化）、运动日标记；蛋白 = 当前体重×1.5g 固定；碳水池 = 目标体重×2.5×N；脂肪池 = 目标体重×cfc×N；日型分配 高/中/低 = ×50%/2、35%/2.2、15%/2（周期线性放大）；运动日优先高→中碳位，默认轮播 高·中·低·低·中·高·低 |
| 食物库 | 内置 200+ 食物（9 分类）；模糊搜索（防抖 300ms）+ 分类筛选 + 历史搜索 + 热门；自定义添加（名称唯一 / 宏量 ±10% 校验 / 被引用软删）；单位换算 g/个/碗/勺；实际摄入 = 每 100g 值 × 份量/100 |
| 饮食记录 | 餐别早/午/晚/加餐 + 智能推荐；食物库选择或手动输入（保底）；增删改 + 当日实时累计；进度条三色（绿 80–100% / 黄 <80% / 红 >100% +「已超标 XXg」）+ 微调建议 |
| 提醒 | 总开关 + 三餐独立开关/时间（默认 08:30/12:00/18:30）；每日单次，已记录不重复；微信订阅消息（`wx.requestSubscribeMessage()` 首次引导授权） |

## 范围外（一期不做）

拍照识别 / AI 识物 / 条形码；运动课程 / 社交 / 打卡 / 榜单；付费 / 广告 / 营销；自动体重曲线 / 全自动复盘 / 详细微量元素；食物收藏、食物库云端同步 / 社区共享、误删 7 天恢复（均为二期）。

## 验收标准

1. 全部核心功能流程通畅，无致命 bug、无卡顿。
2. 所有计算逻辑（BMR/TDEE/碳循环图片公式/532 占比）、周期逻辑、体重调碳逻辑 100% 闭环生效。
3. 数据永久留存、模式切换重置周期正常生效。
4. 小白零学习成本可完整使用全流程（对照 §6 原型 16 页逐一走查）。
5. **重点验收（图片公式）**：当前 57kg、目标 55kg、cfc=0.8、周期 7 天 → 三日型「碳水+脂肪」= 241/23、153/49、72/77（±1g），蛋白 86g/天。
6. 非功能：首屏 ≤2s、页面切换 ≤300ms、计算展示 ≤100ms、提交 ≤1s、搜索 ≤200ms；微信 iOS 12+/Android 8+/微信 8.0+。

## 数据模型（概要，详见含食物库版 PRD §7）

`users`（openid/昵称/头像/注册登录时间）、`user_body`（性别/年龄/身高/体重/目标体重/活动系数/BMR/TDEE/缺口/目标宏量）、`foods`（名称/分类/每 100g 热量与三宏/内置或自定义/单位换算 JSON/软删状态）、`diet_records`（用户/日期/餐别/来源/食物快照/份量单位/宏量热量/备注）、`user_reminders`（总开关/三餐开关与时间/订阅授权）。

> 建表细则以 [开发规范](../../../../doscFile/03-开发规范.md) §4（软删 / 生成列活跃唯一 / DOUBLE 存克数）为准。
