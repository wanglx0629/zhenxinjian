## Purpose

在 change12 拍照识别单模型链路之上，新增主模型故障转移与 Redis 熔断降级：主模型遇到限流/服务端/网络类临时故障时按配置顺序切换备用视觉模型；对密钥/参数类请求错误不转移；对持续故障的模型做短期熔断锁定，避免每次请求都先撞故障模型。能力对调用方透明，识别返回结构与口径不变。

## ADDED Requirements

### Requirement: 主模型故障转移

系统 SHALL 支持配置一个主视觉模型（`ocr.model`）与有序备用模型列表（`ocr.fallback-models`，JSON 数组，默认空数组）。一次识别请求中，当前模型返回「可转移错误」（HTTP 429 限流、5xx 服务端错误、404、408 或网络/超时）时，系统 MUST 按列表顺序尝试下一个模型，直到某个模型成功或候选耗尽；返回「不可转移错误」（HTTP 401/403 密钥问题、400/422 参数或图片问题及其余 4xx）时 MUST 立即终止并返回识别失败，MUST NOT 尝试备用模型。`ocr.fallback-models` 为空数组时，系统 MUST 退化为 change12 的单模型行为。

#### Scenario: 主模型限流时切换备用模型成功

- **WHEN** 主模型返回 HTTP 429，且 `ocr.fallback-models` 配置了可用备用模型
- **THEN** 系统改用第一个备用模型调用并成功返回候选，响应结构与单模型时一致

#### Scenario: 密钥错误不转移

- **WHEN** 主模型返回 HTTP 401（api-key 无效）
- **THEN** 系统立即返回识别失败业务错误，不调用任何备用模型，也不写入该模型的熔断状态

#### Scenario: 备用列表为空时退化为单模型

- **WHEN** `ocr.fallback-models` 为空数组或缺省
- **THEN** 仅调用 `ocr.model`；其可转移错误在尝试（含解析重试）耗尽后返回失败，行为与 change12 一致

#### Scenario: 候选链去重去空

- **WHEN** 备用列表包含空串、与主模型重名或彼此重复的模型名
- **THEN** 实际调用链按「主模型在前、备用保序」去重并忽略空白项，同一模型在一次请求内最多调用一次

### Requirement: 模型熔断降级与自动恢复

系统 SHALL 以 Redis 记录每个模型的连续可转移失败次数与熔断状态：失败计数键 TTL 与熔断窗口对齐；当某模型在窗口内连续失败次数达到 `ocr.circuit-fail-threshold`（默认 3，下限 1）时，MUST 写入带 TTL 的熔断标记（TTL=`ocr.circuit-open-seconds`，默认 300 秒，下限 1 秒）。熔断标记存在期间，识别请求 MUST 直接跳过该模型。熔断标记到期后 MUST 自动放行一次试探调用：试探成功则清除该模型失败计数与熔断标记，试探失败则重新计数。任一模型调用成功 MUST 立即清除其失败计数与熔断标记。所有候选模型都处于熔断或都失败时，系统 MUST 快速失败并返回统一「识别繁忙，请稍后再试」业务错误，且 MUST NOT 递增用户当日识别计数。

#### Scenario: 连续失败达阈值后熔断锁定

- **WHEN** 主模型在窗口内连续返回可转移错误达到阈值次数
- **THEN** 后续识别请求不再调用主模型，直接从首个未熔断的备用模型开始

#### Scenario: 熔断到期自动试探恢复

- **WHEN** 某模型熔断标记 TTL 到期后该模型被再次调用且成功
- **THEN** 其熔断标记与失败计数被清除，后续请求恢复以该模型为候选

#### Scenario: 成功立即清除熔断状态

- **WHEN** 一个处于失败计数累积中（未熔断）的模型本次调用成功
- **THEN** 其失败计数键被删除，不因历史失败而被熔断

#### Scenario: 全部模型不可用时快速失败且不计次

- **WHEN** 主模型与所有备用模型均处于熔断窗口（或本次均返回可转移错误）
- **THEN** 返回「识别繁忙，请稍后再试」业务错误，不产生指纹缓存写入，用户当日识别剩余次数不变

### Requirement: 故障转移相关配置热切换

系统 SHALL 从 `project_config` 读取 `ocr.fallback-models`（JSON 数组）、`ocr.circuit-fail-threshold`、`ocr.circuit-open-seconds`，后台修改后下一次请求 MUST 即时生效（无需重启）；非法 JSON 数组值 MUST 按空列表处理且不阻断识别（fail-open），阈值/时长非法或缺失 MUST 使用默认值。

#### Scenario: 后台调整备用模型即时生效

- **WHEN** admin 在系统配置页把 `ocr.fallback-models` 从 `[]` 改为包含某备用模型
- **THEN** 下一次识别在主模型可转移失败时即按新列表切换，无需重启服务
