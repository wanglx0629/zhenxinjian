## 5. 核心业务流（一期）

```
首次进入（游客 3 天完整体验）
  → 微信授权登录（游客数据自动迁移合并）
  → 录入身体数据（性别/年龄/身高/体重/目标体重/活动系数）
  → 选择减脂模式：532 碳水渐降 | 碳循环
  → 选择热量缺口 X：温 200 / 标 300 / 积 400 / 500（默认 200）
  → 每日记录饮食（食物库搜索 + 份量）→ 实时累计 / 超标提示
  → 每周一空腹称重 → 平台期检测（7 天波动 < 0.3kg）→ 触发阶段 4 微调
```

## 6. 关键计算口径（开发唯一口径，9/3 图片公式定稿）

| 指标 | 公式 / 规则 |
| ---- | ---- |
| BMR（Mifflin-St Jeor） | 女 `10W+6.25H−5A−161`；男 `10W+6.25H−5A+5` |
| TDEE | BMR × 活动系数（久坐 1.2 / 轻度 1.375 / 中度 1.55 / 高度 1.725） |
| 基准热量 | TDEE − X（两模式共用） |
| 532 配比 | 碳 50% / 蛋白 30% / 脂肪 20%（硬性写死） |
| 碳循环碳水池 | 目标体重 × 2.5 × cycleDays |
| 碳循环脂肪池 | 目标体重 × cfc（默认 0.8，可调 1.0）× cycleDays |
| 碳循环每日蛋白 | 当前体重 × 1.5g（固定） |
| 日型分配 | 高/中/低 = 总量 × 50%/2.0、35%/2.2、15%/2.0（周期按比例放大） |
| 经期阶段 | 经期 +15g/+60kcal；排卵 +5g/+20kcal；黄体 +10g/+120kcal |
| 平台期 | 近 7 天体重波动 < 0.3kg → 碳水 −20g / 热量 −80kcal（单次，禁连降） |
| 取整 | 单日克数四舍五入；周期总量守恒 ±1g；后端按 double 存储防漂移 |

> 完整实现见 `apps/zhenxinjian-uniapp/src/utils/calculator.ts`；后端为准，前端展示与离线兜底。

## 8. 游客与登录（PRD §2.1）

1. 首次进入默认 **3 天完整功能游客体验**（无阉割），从前端首次打开计时。
2. 进入第 4 天 0 点弹**不可关闭**的强制授权弹窗（仅可授权登录 / 退出小程序）。
3. 游客数据临时留存；登录后自动迁移合并；过期未登录临时数据保留 7 天后清空。
4. 游客时效 / 权限 / 数据迁移**由后端校验**，前端计时仅展示。

## 9. 开发红线（摘要，全文见 Constitutions.md §5）

- 核心计算逻辑**后置后端**，人体数据区间前后端双重校验。
- 错误文案进 `ExceptionConstant`；接口统一返回 `Result`。
- 文件头注释：`作者: wanglx`。
- 禁止：硬编码密钥、CORS `*`、无 TTL 会话 Key、BigKey、Controller 拼 SQL。
- 禁止私自实现一期范围外功能（AI 识物 / 社交 / 付费 / 运动课程等）。

## 10. 数据留存规则

| 数据 | 规则 |
| ---- | ---- |
| 用户全部数据 | 永久云端留存，不自动清空 |
| 切换减脂模式 | 自动终止当前周期、清空当期进度、重启全新周期 |
| 游客临时数据 | 登录后合并；过期 7 天后清空 |
| 历史饮食记录 | 永久留存（自定义食物被引用后软删，不物理删除） |
