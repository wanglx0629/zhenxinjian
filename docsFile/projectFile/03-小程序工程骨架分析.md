> 来源：`MRD-PRD/小程序工程骨架（完整版·zip）/miniprogram/`（原生微信小程序实现，提取分析）
> 整理日期：2026-09-08　|　结论：**算法与常量层全量采纳（已 TS 移植 + 48 项对拍验证）；页面层与云函数层不采纳**，按 UniApp 工程规范重建。

---

## 1. 这是什么

PM 交付的**原生微信小程序参考实现**，实现了 PRD V1.1 的一期全流程（游客体验 → 登录 → 录入 → 双模式计划 → 每日记录 → 体重跟踪 → 平台期）。它不是空骨架，而是「可跑通的计算真源」——其 `utils/calculator.js` 与 PRD 图片公式、高保真原型逐位一致。

本项目技术选型为 **UniApp（Vue3 + TS）**，故不做整体搬运，而是：**逻辑层移植 + 表现层重写**。

## 4. 采纳情况

### 4.1 已采纳（5 个文件 → TypeScript 移植）

| 原文件 | 移植到 | 说明 |
| ---- | ---- | ---- |
| config/constants.js | `apps/zhenxinjian-uniapp/src/config/constants.ts` | 补齐 `as const`、接口定义（RangeCfg/PeriodPhaseCfg/Stage532）；口径零改动 |
| utils/calculator.js | `apps/zhenxinjian-uniapp/src/utils/calculator.ts` | 12 个函数全量移植 + 全部入参/出参类型化（CalcProfile/MacroResult/PhaseInfo 等） |
| utils/validate.js | `apps/zhenxinjian-uniapp/src/utils/validate.ts` | checkRange/checkAll/checkTargetWeight |
| utils/format.js | `apps/zhenxinjian-uniapp/src/utils/format.ts` | ymd/md/g/week |
| data/foods.js | `apps/zhenxinjian-uniapp/src/data/foods.ts` | 200 条 + FoodItem 接口 |

移植原则：**算法逻辑逐行等价，只加类型不改语义**。浮点取整细节（`round()` 的 half-up 语义、`toFixed(6)` 吸收 IEEE754 噪声）原样保留。

### 4.2 验证方式

原骨架自带 `verify_calc.js`（对拍 PRD 图片示例与高保真原型）。移植后用 esbuild 将 TS 编译为 CJS 跑同款断言：

- **48 / 48 断言通过**，覆盖：
  - BMR/TDEE/532 基准（1252 / 1721 / 190-114-34-1521）
  - 碳循环三池与三日型（962.5 / 308 / 85.5；高 240.6-23.1 / 中 153.1-49.0 / 低 72.2-77.0）
  - 经期四阶段跨 12 个日期的判定（含跨周期回绕 dayIdx=1）
  - 532 今日目标叠加经期（190+15 / 1521+60）
  - 阶段 4 微调（−20g / −80kcal）
  - 食物换算（150g 米饭 = 38.9-3.9-0.5 → 175kcal）
  - 超标判定与男性/未开启返回 null 分支

### 4.3 未采纳及原因

| 部分 | 原因 | 替代方案 |
| ---- | ---- | ---- |
| pages/*（wxml/wxss/js） | 原生语法与 UniApp Vue3 不兼容；项目有自身设计系统 | 按 PRD/原型用 Vue3 SFC 重建，逻辑调用已移植的 TS 模块 |
| cloudfunctions/*（login/saveRecord/sendRemind） | 项目后端为自建 Spring Boot，云函数仅是骨架演示 | 后端统一接口 + JWT；提醒走后端定时任务 |
| utils/store.js | uniapp 已有 storage.ts（Token），数据留存走后端 MySQL | 游客数据按 PRD §2.1 由后端校验与合并迁移 |
| database/init.js | 云数据库初始化脚本 | 后端食物库表 + foods_200.json 导入 |
| project.config.json / sitemap.json | 平台私有配置 | UniApp 编译产物自动生成 |

## 5. 可复用的业务细节（从骨架代码提炼）

- **存储键规范**：本地缓存统一 `zxj_` 前缀；饮食记录按 `records_{yyyy-MM-dd}` 日期分桶，天然支持跨天切换与按日加载。
- **游客合并策略**：登录后将 `profile` / `weights` 复制为 `profile_{openid}` / `weights_{openid}`，不清除原数据。
- **导航主色**：#0D9488（teal），页面底 #F6F8F8——与设计系统文档一致。
- **超标提示文案结构**：`{宏量}超{差值}{单位}` 逐项拼接 + 一句建议（不拦截、只提示）。
- **模式切换确认**：switch 页二次确认后才执行「终止周期 + 清进度 + 重启」，避免误触。

## 6. 对本项目的迁移结论

| 关注点 | 结论 |
| ---- | ---- |
| 计算正确性 | 以移植后的 calculator.ts + 后端双实现为准，任何改动须重跑对拍断言 |
| 常量口径 | constants.ts 为唯一前端口径源，改口径 = 改 PRD，二者联动 |
| 页面顺序参考 | 16 页流程可作为 UniApp 页面路由设计（pages.json）与验收清单 |
| 云函数 | 全部废弃，对应能力由后端 /auth /record /weight 接口承接 |
