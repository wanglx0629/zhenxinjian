## 一、3 分钟跑起来

1. 下载并安装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)（稳定版）
2. 打开工具 → 「导入项目」→ 目录选择 **`miniprogram/`**
3. AppID：没有就选「测试号」，能完整预览功能（真机预览需正式 AppID）
4. 后端服务：若无云开发环境，先注释掉 `cloudfunctions/` 相关内容即可离线跑通全部前端逻辑
5. 点击「编译」→ 模拟器出现登录页即成功

> ⚠️ 导入时选择 **`miniprogram` 目录本身**，不要选父目录，否则 `app.json` 找不到会报「未找到入口文件」。

## 三、核心算法（utils/calculator.js）

**这是整个产品的心脏，已与高保真原型逐行对拍一致，请勿随意改动。**
任何修改都必须同步更新原型与 PRD，并跑通 `verify_calc.js` 的 44 项断言。

### 1. 基础代谢与基准热量

```
BMR  = 10 × 体重(kg) + 6.25 × 身高(cm) − 5 × 年龄 + (男 +5 / 女 −161)   [Mifflin-St Jeor]
TDEE = BMR × 活动系数
基准热量 = TDEE − 用户自选缺口 X          ← 532 与碳循环共用同一个基准
```

### 2. 532 碳水渐降模式

```
碳水 = 基准热量 × 50% ÷ 4
蛋白 = 基准热量 × 30% ÷ 4
脂肪 = 基准热量 × 20% ÷ 9
```

四阶段（P08）：

| 阶段 | 调整 | 说明 |
|---|---|---|
| 1 月初适应期 | 基准 | 固定 50/30/20，不做降碳 |
| 2 稳步减脂期 | **+ 经期阶段上浮** | 按当前经期阶段动态叠加 |
| 3 经后高效期 | 基准 | 梯度小幅降碳 |
| 4 平台突破期 | 碳水 −20g，热量 −80 kcal | 蛋白脂肪不变 |

### 3. 碳循环模式（PRD 图片公式）

```
7 天总碳水 = 目标体重 × 2.5 × 周期天数 N
7 天总脂肪 = 目标体重 × 脂肪系数 × N        （系数 0.8 / 1.0，默认 0.8）
每日蛋白   = 当前体重 × 1.5                 （周期内固定不变）

周倍数 w = N / 7
高碳日：碳水 = 总碳水 × 50% ÷ (2.0×w)   脂肪 = 总脂肪 × 15% ÷ (2.0×w)
中碳日：碳水 = 总碳水 × 35% ÷ (2.2×w)   脂肪 = 总脂肪 × 35% ÷ (2.2×w)
低碳日：碳水 = 总碳水 × 15% ÷ (2.0×w)   脂肪 = 总脂肪 × 50% ÷ (2.0×w)

日序模板：高 / 中 / 低 / 低 / 中 / 高 / 低
运动日智能适配：运动日优先占高碳位，其次中碳位
```

### 4. 经期四阶段（女性专属 F18 / F29）

以「今天」相对经期开始日的天数对周期长度取模，得到周期第几天 `dayIdx`：

| 阶段 | 判定 | 碳水上浮 | 热量上浮 | 饮食重点 |
|---|---|---|---|---|
| 经期 menstrual | dayIdx ≤ 经期天数 D | +15 g | +60 kcal | 补铁温补、避寒凉 |
| 卵泡期 follicular | D < dayIdx ≤ L−14 | 0 | 0 | 基线，稳步推进缺口 |
| 排卵期 ovulation | L−14 < dayIdx ≤ L−12 | +5 g | +20 kcal | 控量、补镁锌 |
| 黄体期 luteal | dayIdx > L−12 | +10 g | +120 kcal | 控盐补钙镁、防暴食 |

非女性 / 未开启 / 无有效日期时返回 `null`，方案回落基准。

### 5. 运行自测

```bash
cd miniprogram
node verify_calc.js
```

覆盖 7 组共 44 项断言：BMR/TDEE、碳循环图片示例（240.6/153.1/72.2 等）、
经期四阶段 12 个日期点、532 叠加经期、四阶段微调、食物换算、超标比对。

## 五、数据口径（务必遵守）

1. **食物营养数据**为每 **100g 可食部**，仅保留碳水 / 蛋白质 / 脂肪三项；
   能量按 4 / 4 / 9 换算，是参考值而非成分表原值。
2. **干制品一律按干重标注**，不做泡发换算。名称保留「（干）」后缀，
   称重页需提示「请按干重称重」。（PM 已确认口径）
3. 单位统一：重量 `g`、能量 `kcal`、身高 `cm`、体重 `kg`。
4. 区间校验以 `config/constants.js` 的 `RANGES` 为准，越界前端拒绝并兜底。
