## 1. 数据来源与版本

## 3. 字段定义

```typescript
interface FoodItem {
  id: string       // 食物编号，F001 ~ F200，唯一
  category: string // 分类（含两位编号前缀，如 '01 谷薯杂豆·主食'）
  name: string     // 食物名称；干制品保留「（干）」后缀；烹调态标注（蒸/煮/生）
  alias: string    // 别名/俗称（搜索用，可为空，如 '白米饭' '车厘子' '大闸蟹'）
  carb: number     // 碳水化合物 g / 100g（1 位小数）
  protein: number  // 蛋白质 g / 100g（1 位小数）
  fat: number      // 脂肪 g / 100g（1 位小数）
  kcal: number     // 能量 kcal / 100g（整数，按 4/4/9 换算的参考值）
  serving: number  // 常用单份份量 g（添加记录时的默认克数）
}
```

## 4. 口径规则（PM 已确认）

| # | 规则 | 说明 |
| -- | ---- | ---- |
| D1 | 每 100g 可食部 | 所有营养值统一口径，录入时按 `值 × 克数 ÷ 100` 换算 |
| D2 | 能量按 4/4/9 换算 | `kcal = 碳水×4 + 蛋白×4 + 脂肪×9`，与成分表实测值存在 **最大 ±0.5** 偏差（已全量校验：200 条最大偏差恰为 0.5，无超限项） |
| D3 | 干制品按干重 | 香菇（干）、黑木耳（干）、银耳（干）、腐竹等一律标干重，**不做泡发换算** |
| D4 | 烹调态单列 | 同一食物生/熟分列两条（如大米 F001 生 vs 米饭 F002 蒸），营养密度差异大，不可合并 |
| D5 | 酒精不计能 | 白酒（F196）宏量全 0、kcal=0——4/4/9 公式不含酒精（7 kcal/g），属已知口径局限；展示层可另加「饮酒提示」，但一期不扩数据 |
| D6 | serving 范围 5–500g | 常用份量参考值（如香油 5g、奶茶 500g），仅作默认值，用户可改 |

## 6. 运行时使用位置

| 层 | 位置 | 职责 |
| ---- | ---- | ---- |
| 小程序离线兜底 | `apps/zhenxinjian-uniapp/src/data/foods.ts` | 无网/后端不可用时的检索与换算（200 条全量内置） |
| 后端食物库（规划） | MySQL `food` 表（待建） | 权威数据源，支持后续运营扩充与自定义食物 |
| 数据导入 | `MRD-PRD/foods_200.json（开发导入用）.json` | 后端建库时的批量导入源 |

### 后端导入建议（表结构要点）

- 字段与 `FoodItem` 一一对应：`id`(业务编号 F001–F200)、`category`、`name`、`alias`、`carb`、`protein`、`fat`、`kcal`、`serving`。
- 营养值用 `DECIMAL(5,1)` 存储防止浮点漂移；`kcal` 用 `INT`。
- `name` 建索引（搜索主键）；`alias` 支持全文检索或冗余搜索词字段。
- 基础库数据（200 条）与用户自定义食物分表或加 `is_custom`/`user_id` 隔离；自定义食物被饮食记录引用后**软删不物理删**（宪法数据留存规则）。
- 遵守项目软删规范：`deleted` 字段 + 活跃唯一约束 `uk_name_active(name, deleted)`。

## 7. 质量校验记录（2026-09-08）

- 条目数：200（F001–F200 连续无断号）。
- kcal 与宏量 4/4/9 换算偏差：最大 0.5（F010 荞麦面），全部 ≤ ±0.5 容差，无超限。
- serving 范围：5–500g，无空值。
- 分类连续性：蔬菜与菌藻在 F142 处衔接（菌藻 F142–F150 共 9 条，编号按分类首条对齐）。
